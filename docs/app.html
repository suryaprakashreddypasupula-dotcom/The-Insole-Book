How the website is put together

Three files drive almost every click: the page shell, the lesson text, and the viewer. Change text in one place. Change 3D in another. You still never deploy.

1. The three files that matter

FileJob
index.htmlChrome of the site: intro overlay, syllabus, 3D stage, lesson pane, library, styles. No chapter prose here.
content.jsThe course. CHAPTERS is the syllabus order. GLOSSARY is the dotted-term popovers. Edit this to change what a student reads.
app.jsLoads Three.js, reads catalog.json, flies the camera, plays lift / press / flip / drape, runs Training callouts.

Three.js itself is already inside vendor/. The site does not download libraries from the internet.

2. What happens when the page loads

  1. A small script in index.html runs the logo, then the video once, then hides the overlay. Deep links (#lesson=1.4) skip that.
  2. app.js fetches catalog.json, draws the syllabus from CHAPTERS, draws the library, and loads the first lesson’s GLB onto the stage.
  3. Click a syllabus row or a bottom chapter chip → the reader scrolls into view and renderLesson() swaps models and the first step’s camera.
  4. Next / Back or arrow keys / space move state.step, then state.lesson, then the next chapter.

3. The syllabus flow (what the student walks)

  1. Meet the insole — landmarks, plantar map, Functional vs Diabetic.
  2. Bases — Bi-Lam vs Tri-Lam (Hike internal company names Sweet / Double / Triple for the finished insole, then durometer, BYO), then Shell / Cork / Co-Poly mimic, then the real UCBL.
  3. Accommodations — what one is, then met bar → pad → neuroma → offload → plug → drill & fill → dancer’s → toe crest → Morton → arch → cuboid / fifth → heel pad & spur → intrinsic then extrinsic wedges.
  4. Top covers — how the sheet is glued heel-first, then T1–T14 at true thickness.
  5. Combinations — Charcot, leftover toolbox names, a stacked shell prescription.

The library under the reader is the same devices grouped the same way. Every library card that has an add-on can Replay.

4. How a lesson is written

One lesson is a small object in content.js:

{
  id: "met-bar",
  title: "Met Bar",
  models: [{ po: "PAIR-MET-BAR", side: "LEFT" }],
  camera: "pad",
  steps: [
    { camera: "pad", text: "…" },
    { camera: "profile", anim: "separate", text: "…" },
    { camera: "pad", anim: "reseat", text: "…" }
  ]
}
  • po must match a catalog.json row.
  • compare: [{ po, side, label }, …] puts two devices on stage.
  • covers: true shows the T1–T14 chips. step.cover: "T3" pins a sheet.
  • {{P-Cell}} in the text becomes a glossary tap.
  • anim values: separate / reseat (lift), press / release, flip / attach / settle, seat (drape down).

After you save content.js, refresh the book. No Python.

5. Cameras and motion (what “Apple-graded” is in code)

The whole insole stays in frame. Named views only change angle and lean (overview, profile, heel, arch, forefoot, toes, pad, relief, heelProfile, forefootEdge). They do not crop the heel off.

Replay on a pair: the part leaves, then returns. For lift/press, the teaching color then fades. Training on covers: pills and leader dots, not a magnifier over the model.

7. Copying the book to another Mac (still no deploy)

  1. Copy the whole hike-insole-book folder (USB or AirDrop).
  2. On that Mac, double-click Start Book.command or run the two Terminal lines from Page 1.
  3. That Mac needs Python 3 (already on macOS) and a browser. It does not need the Ops Agent venv unless someone will rebuild GLBs there.
Still not a public website. To put this on the internet you would later pick a host. That is a separate decision. As built, it is a local HTML app.
